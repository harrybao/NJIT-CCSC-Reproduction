## 0. 先说结论（一页版）

1. **Citation 按钮都点了。**
   * 你开放网络之后，CCSC 页面能打开了。页面上正好有 19 个工具，就是 GitHub `ccsc-tools` 下的那 19 个仓库。
   * 每个工具的 **Citation 按钮指向一个 Zenodo 软件存档**，不是期刊论文。
   * 第一天 Zenodo 一直返回 504（网关超时），所以我改用 DataCite 解析了全部 19 个 DOI，拿到了 APA、BibTeX 和完整元数据，存放在 `papers/citations/`。
   * 其中 13 个存档对应 GitHub 的某个 release tag（例如 LSTM v1.0.2、SYMHnet v1.0），我按这些**被引版本**重跑或做了 diff。
   * 另外 6 个是直接上传到 Zenodo 的压缩包（SolarCNN、MIST、DeepHMI、SINet、LLMFlare、DeepGeoCME），我跑的是 GitHub 最新版。第二天 Zenodo 恢复了，我逐个文件核对了这些压缩包：
     * DeepHMI、SINet、LLMFlare、DeepGeoCME 和 GitHub 版本内容一致，差异只是换行符；DeepGeoCME 的模型文件也一致。
     * MIST 的存档版 `test.py` 少了一行 `import os`，按原样运行会直接报错，GitHub 版已修好。存档里还多了一个 GitHub 上没有的训练集 `X_train.npy`。
     * SolarCNN 的记录是**受限访问**，文件不公开，无法核对。
   * **CCDC 页面**的标题是 "Community Coordinated Data Center"，目前只列了 **FlareDB** 一个数据集。
2. **复现情况**（全部在 4 核 CPU、无 GPU 的环境里完成，用于对比的论文全文共 16 篇）：
   * **工具和论文两个层面都复现了：** SINet（F10.7 RMSE 3.88 / 16.32，与论文一致）、DeepGeoCME（TSS 0.757，与论文一致）。
   * **工具层面复现了，但论文自己的评估无法用发布包重跑：**
     * SEP（12/12 逐位一致）；
     * **SDNN**（5 张输出图与作者存档 r = 1.000000）；
     * **FibrilNet**（与存档掩膜的 IoU 0.901，等于我自己两次随机运行之间的 IoU 0.900）；
     * SolarUnet（逐字节一致）；
     * Kp（在随机性范围内一致）。
   * **部分复现：** SolarCNN、LSTM、RNN-CME、SolarFlareNet、SYMHnet、MIST、FlareML、TSInet、CMETNet。
     * SolarCNN 的权重是从作者 Google Drive 下载的，预测与存档误差为 3e-5 G；加上训练时的归一化后，SSIM 从 0.812 提升到 0.892，和论文的提升幅度相当，但只有 3 个样本。
     * 其余工具：发布包能复现自己存档的输出，但达不到论文的数字，或者评估方式和论文不一样。
   * **尝试但失败：** Dst（发布版用 0.9×真实值替换预测）。
   * **被阻塞：**
     * DeepHMI：需要约 37 CPU 小时；
     * MagNet：包里缺了 `layers/attention.py`。
   * **没有尝试：** LLMFlare，需要你授权付费 API 和 GPU。
3. **最重要的发现，和你邮件里的主题（外部验证、数据质量）高度相关：**
   * **MIST：** README 报告的 TSS 0.906 来自"重叠滑动窗口 + 随机划分"。95.6% 的测试窗口在训练集里都有一个与之重叠 23/24 小时的"邻居"。我把同一个预训练模型拿到**时间和活动区都独立**的 2015–2018 数据上测试，TSS 只有 **0.197**（AUC 从 0.997 降到 0.833）。而 2019 年那篇 LSTM 论文在同一份测试集上的 TSS 约为 0.73。这正是你邮件里说的"out-of-sample validation"问题的一个具体实例。
   * **Dst Transformer：** 发布版测试代码 `predict()` 会读取测试标签：只要预测值和真实值"不够离谱"，就把它替换成 **0.9 × 真实值**，结果 88–90% 的"预测值"恰好等于 0.9×标签。原始网络输出的 R² 只有 0.06–0.38，在每个预测时长上都不如"持续性预报"（用当前值预测未来）。
   * **SolarFlareNet：** 仓库自带的 9 个模型里，8 个在自带测试集上没有判别能力（AUC 0.40–0.53），作者自己存档的结果文件也是如此。唯一有效的 C/24h 模型是后来重训的，而它的训练文件包含了 84% 的测试行。
   * **SYMHnet：** 发布版测试流程实际上是在预测**下一行**（1 分钟或 5 分钟之后），而不是 1–2 小时之后；1h 和 2h 两个数据目录的文件完全相同（MD5 一致）。用被引的 v1.0 版本重跑后，第 31、33、42 号地磁暴的 RMSE 与论文 Table 8/9 相差约 2% 以内，说明论文的数字很可能就是用这个"预测下一行"的流程算出来的。
   * **RNN-CME：** 发布包里同一批样本存了两份，18 个特征列的**顺序不一样**。按物理常识（广延量应与 USFLUX 强相关）判断，只有 `CME_data_samples` 那份的列名是对的，而模型恰恰是用另一份训练的；代码里的特征排序在"错误的列名"下正好等于论文 Table 2 的排名。用发布的模型在论文自己的测试集上打分，GRU 的 TSS 为 0.31–0.49，而论文是 0.45–0.60。
   * **SolarCNN：** `test.py` 漏掉了训练时的归一化，所以随仓库提供的预测图看起来没有任何提升。补上归一化后提升就出来了，这是一个发布代码层面的问题。
   * **CMETNet：** 训练脚本在"测试年份"上挑选 10 次随机训练中 MAE 最低的那次，属于测试集选择偏差。
   * 也有**做得好的地方**：LSTM 论文的 Table 2 数据集按时间切分（2010–2013 训练 / 2014 验证 / 2015–2018 测试），而且训练和测试之间**没有共享任何活动区**，这是非常规范的 leakage-aware 划分。我用它重训了 10 个随机种子，≥M5.0 的 TSS 为 0.877±0.035（测试集最优阈值）。
4. **对你的意义：** 这些发现本身就是一个很好的"Data Science 视角下的科学 ML 可靠性"研究故事，和 NSF 26-512 "AI-Ready Datasets" 计划的方向一致（截止日期 2026-11-04，已在 nsf.gov 上核实）。但**措辞必须非常克制**：现在我们能读到大部分论文全文，但看不到论文的原始实验代码；"发布包和论文对不上"不等于"论文做错了"。具体怎么跟 Jason 讲，见第 6 节。

## 1. 太阳物理/空间天气背景速成

| 概念 | 一句话解释 | 在哪些工具里出现 |
|---|---|---|
| **活动区 (Active Region, AR)** | 太阳表面磁场很强的区域（黑子群），NOAA 给它们编号，例如 AR 12673。耀斑和 CME 大多从这里爆发。 | 几乎所有耀斑/CME/SEP 工具 |
| **SDO/HMI** | NASA 太阳动力学天文台上的日震与磁成像仪，2010 年起提供全日面**矢量磁图**（三个分量 Bx、By、Bz），720 秒一张。 | SHARP 相关工具、DeepHMI、SolarCNN 的标签 |
| **SOHO/MDI** | HMI 的前代仪器（1996–2011），只有**视向（LOS）磁图**，分辨率更低。覆盖第 23 太阳周（比第 24 周更强）。 | SolarCNN、MagNet |
| **SHARP 参数** | 由 HMI 矢量磁图对每个活动区计算出的约 25 个物理量，例如 TOTUSJH（总无符号电流螺度）、USFLUX（总无符号磁通量）、R_VALUE（极性反转线附近的磁通）、TOTPOT（总自由磁能代理量）等。可以理解为"活动区的表格型特征"。 | FlareML、LSTM、SolarFlareNet、SEP、RNN-CME、MIST |
| **耀斑等级（GOES X 射线）** | 按 1–8 Å 软 X 射线峰值通量分级：A < B < C < M < X，每级相差 10 倍；"M5.0" 指 5×10⁻⁵ W/m²。"≥M" 指 M 级及以上。 | 所有耀斑工具 |
| **NCEI / DONKI** | NOAA 的耀斑目录 / NASA 的空间天气事件数据库（记录耀斑、CME、SEP 之间的关联）。 | 标签来源 |
| **CME（日冕物质抛射）** | 大量等离子体和磁场被抛入行星际空间；若朝向地球，可引发地磁暴。 | RNN-CME、CMETNet、DeepGeoCME |
| **SEP（太阳高能粒子）** | 耀斑或 CME 加速出的高能质子，对宇航员和卫星有辐射危害。 | SEP-prediction |
| **地磁指数 Dst / SYM-H / Kp** | 衡量地磁暴强度的指数。Dst（小时值）和 SYM-H（1 分钟值）越负，暴越强；Kp 取 0–9，越大越强。 | Dst、SYMHnet、Kp |
| **太阳风参数** | L1 点卫星测得的行星际磁场（尤其是 Bz 南向分量）、太阳风速度、密度、动压、电场等，来自 NASA OMNIWeb。 | Dst、Kp、SYMHnet、CMETNet |
| **F10.7 / F30** | 10.7 cm / 30 cm 波长的太阳射电流量，是太阳活动水平的"体温计"，用于高层大气密度和卫星轨道衰减模型。 | SINet |
| **TSI（总太阳辐照度）** | 太阳在 1 AU 处的总辐射功率，约 1361 W/m²，变化只有约 0.1%。是气候研究的重要输入。 | TSInet |
| **BBSO / GST / NIRIS** | 大熊湖太阳天文台（NJIT 运营）的 1.6 m Goode 太阳望远镜，以及其近红外成像光谱偏振仪，分辨率远高于 HMI，但视场小、只有部分时间有观测。 | SolarUnet、FibrilNet、SDNN、DeepHMI |
| **Hα 图像 / 纤维 (fibril)** | Hα 是 656.3 nm 的氢谱线，可以显示色球层结构；纤维是沿磁力线排列的细长暗结构，可以用来推断磁场方向。 | FibrilNet、MagNet |
| **Stokes 反演** | 偏振光谱（Stokes I、Q、U、V）经物理模型（如 Milne–Eddington）反演得到磁场和速度。传统方法很慢，所以用神经网络来近似。 | SDNN |
| **SWAMIS** | 传统的磁特征识别与跟踪软件（基于阈值），SolarUnet 用它的输出作为训练标签。 | SolarUnet |

## 2. 评价指标（以及为什么这样选）

**二分类（耀斑 / CME / SEP 预报）**，混淆矩阵记为 TP、FN、FP、TN：

* **Recall（召回率）= TP/(TP+FN)**：真实事件中被预报到的比例。
* **Precision（精确率）= TP/(TP+FP)**：发出的警报中真正发生的比例。在类别极不平衡时通常很低。
* **ACC（准确率）**：类别不平衡时会误导人。例如 ≥M5.0 的正例只占约 0.4%，全部预测为"否"也能得到 99.6% 的准确率。
* **BACC（平衡准确率）** = (recall + specificity)/2。
* **TSS（真技巧评分）= recall − FPR**，取值 −1 到 1。**空间天气领域最常用**，因为它不受正负样本比例影响（Bloomfield et al. 2012 推荐）。TSS=0 表示没有技巧，TSS<0 表示比随机还差（往往是标签方向弄反了）。
* **HSS（Heidke 技巧评分）**：相对于"随机猜测"的改进，受类别比例影响。
* **Brier Score / BSS**：用于概率预报，衡量预报概率与实际 0/1 结果之间的均方误差；BSS 是相对于"气候学基准"的改进比例。
* **AUC**：与阈值无关的排序能力，0.5 代表随机。

**回归（Dst、Kp、SYM-H、F10.7、TSI、CME 到达时间）**：

* **RMSE / MAE**：误差的大小（单位分别是 nT、小时、W/m² 等）。
* **R² / Pearson r**：解释方差的比例 / 线性相关程度。
* **持续性基线（persistence）**：直接用"当前值"作为对未来的预测。对 1 小时后的 Dst、1 分钟后的 SYM-H 这类高度自相关的序列，持续性基线往往非常强。**一个模型要声称有用，至少要先打败持续性基线。** 这是我在多个工具上补做的关键检查。
* **FSS（forecast skill score）**：一般定义为 1 − MSE_model / MSE_reference，参考预报通常取持续性或气候学基准。

**图像（超分辨率、分割）**：

* **SSIM**：结构相似度（亮度、对比度、结构），1 为完全相同。
* **PSNR**：峰值信噪比（dB），越高越好；**它依赖于你设定的数据范围（data_range）**，换一个归一化方式数值就会变。
* **PCC**：像素级皮尔逊相关系数，对线性缩放不敏感。
* **IoU / 像素一致率**：分割掩膜之间的重叠程度。

## 3. 贯穿所有工具的共性问题：数据泄漏与"验证到底验证了什么"

这一节是这次工作的"方法论核心"，也是你 Data Science 背景最能发挥作用的地方。

1. **随机划分 vs 时间/活动区划分。** 太阳数据是强自相关的时间序列：同一个活动区的相邻小时几乎一模一样。如果按样本随机切分，测试样本的"兄弟"往往就在训练集里，模型等于在背答案。
   * 规范做法：LSTM 论文的 Table 2 按时间切分，活动区之间零重叠。
   * 反面例子：MIST（随机切分重叠窗口，TSS 从 0.906 降到 0.197）；SolarFlareNet 自带的测试文件（84% 的行同时出现在训练文件里）。
2. **阈值或模型在测试集上选择。** 只要在测试集上挑"最好的那个"，报告出来的分数就会偏乐观。
   * LSTM Table 5 在测试折上挑选让 TSS 最大的阈值。我量化了它的影响：在 ≥C 上影响很小（0.580 → 0.589），在 ≥M5.0 上影响很大（0.734 → 0.877），因为正样本极少，阈值一动 TSS 就跳。
   * CMETNet 在测试年份上从 10 次训练中挑最好的一次。
   * SEP 在测试集上拟合等距校准（isotonic calibration）。
   * RNN-CME 对每个模型使用固定阈值，这些阈值怎么选出来的不清楚。
3. **归一化统计量包含测试集。** MIST 的 StandardScaler 用全部 84,577 行拟合；FlareML 在测试批次上拟合 scaler；TSInet 用目标序列自身的最小/最大值来缩放输出。
4. **评估路径读取了标签。** Dst 的 `predict()` 会用到 y_test（最严重的一种）。FlareML 的展示函数会改写 RF 的分数，使其低于集成模型。
5. **"预测时长"的实现与描述不一致。** SYMHnet 的 1h 和 2h 数据完全相同，测试目标实际上是下一行；Dst 测试对所有时长都加载 6h 的权重。
6. **有效样本量很小。** SEP 测试集只有 2 个产生 SEP 的活动区；RNN-CME 只有 2 个活动区；SolarCNN 只有 3 张图；DeepHMI 只有 1 张图。在这种情况下，TSS=1.0 的不确定性非常大。
7. **软件工程层面的可复现性问题。** `os.listdir()` 不排序导致文件顺序依赖操作系统（SolarUnet）；命令行参数没有生效（TSInet 缺少 `global` 声明）；特征按"位置"而不是"列名"选取，导致列错位（SolarFlareNet）；模型和数据托管在单一机构的网站上（FibrilNet、SDNN、MagNet），网站一旦访问不了就无法复现。

> 这些全部是**关于发布出来的软件包**的观察。论文正文和原始实验代码我们看不到，所以**不能**据此断言论文的数字是错的。在与教授交流时，请务必保持这个区分。

## 4. 逐个工具讲解（8 点格式）

每个工具按以下 8 点展开：①研究问题 ②输入数据 ③算法 ④运行流程 ⑤输出 ⑥评价指标 ⑦复现情况 ⑧局限性。

### 4.1 FlareML（DeepSun 的后端）

① 已知某天会发生耀斑，预测它是 B、C、M 还是 X 级（4 分类）。
② 845 个耀斑日（2010-05 至 2016-12，472 个活动区），每个样本取耀斑当天 00:00 的 13 个 SHARP 参数（TOTUSJH、TOTBSQ、TOTPOT、USFLUX、R_VALUE 等）。
③ 随机森林（RF）、多层感知机（MLP）、极限学习机（ELM，隐藏层权重随机生成、只训练输出层的一种单隐层网络），再加上三者的多数投票（ENS；平票时采纳 RF 的结果）。
④ 读取 CSV → 去掉非特征列 → 类别字母映射为 1–4 → RF 直接使用原始特征，MLP/ELM 先做标准化 → 三个模型分别预测 → 投票 → 按类别计算 one-vs-rest 的 TSS/BACC 并画柱状图。
⑤ 每个样本一个类别标签。
⑥ 按类别计算的 TSS、BACC。
⑦ 在演示测试集（40 个样本）上，用预训练模型复现了作者日志：ENS acc 0.850，RF 0.825，ELM 0.725，MLP 0.300（MLP 把全部样本预测成 C，作者日志里也是如此）。原始指标见 `results/FlareML/independent_metrics_pretrained.json`。
⑧ 局限：
   * 40 个演示测试样本中有 **31 个同时出现在训练样本里**，所以演示分数不是样本外分数；
   * 展示函数会把 RF 的分数改写为"ENS 减去一个随机数"；
   * MLP/ELM 在测试批次上拟合标准化参数，导致单个样本的预测结果依赖于和它一起测试的其他样本；
   * 只用耀斑当天 00:00 这一个时刻的快照，没有时间序列信息；
   * 4 类严重不平衡（C 级占 65%）。

### 4.2 LSTM-flare-prediction（Liu et al. 2019, ApJ）

① 给定一个活动区在时刻 t 的数据，预测未来 24 小时内会不会发生 ≥M5.0 / ≥M / ≥C 级耀斑。三个阈值各训练一个二分类模型。
② 每小时一个样本，每个样本有 40 个特征：25 个 SHARP 参数，加上 15 个"耀斑历史"特征（例如过去一天发生过多少次 C/M/X 级耀斑、按时间衰减的加权和）。经过特征选择后，三个模型分别使用其中 14、22、20 个。把同一个活动区连续 10 个小时的样本组成一个序列。
③ LSTM（10 个单元）→ 时间注意力（对 10 个时间步加权，再与最后一个隐藏状态拼接）→ 全连接层 200 → 全连接层 500 → softmax。损失函数为加权交叉熵（class_weight='balanced'），训练 7 个 epoch，batch size 256。
④ 读 CSV → 若当前样本存在缺失值则丢弃 → 向前取同一活动区的 9 个历史样本（不足则补零掩码）→ 输入网络得到 P(正类) → 与阈值比较。
⑤ 每个样本输出概率和正/负标签。
⑥ Recall、Precision、ACC、BACC、HSS、**TSS**。
⑦ 复现情况：
   * 被引版本 v1.0.2 自带的演示模型能复现作者存档的演示输出（一致率 99.1–99.5%）。GitHub 最新版换了更新的模型，所以之前和存档对不上。
   * Table 2 数据（样本数与论文 Table 2 完全一致）重训了 10 个种子，测试集为 2015–2018 年：
     * 用**论文写明的阈值**（0.50/0.60/0.50）：TSS 为 0.812 / 0.730 / 0.580，论文 Table 3/4 是 **0.877 / 0.790 / 0.607**，低 0.03–0.07；
     * 用测试集最优阈值：0.877 / 0.748 / 0.589；
     * 用**验证集**选阈值（无泄漏）：0.825 / 0.739 / 0.584。
   * 原论文 Table 5（≥C，10×10 交叉验证）：作者的参考输出（与论文 Table 5 逐位相同）是 TSS 0.612±0.009；我用同一份代码（只加了 4 行 TF2 兼容补丁）在 TF 2.10 下复跑，共训练 100 次、耗时 86 分钟，得到 **TSS 0.581±0.011**，比作者低 0.031，其他指标也都略低。我怀疑是 Keras 2.2.4 与 TF2 中 LSTM 默认激活函数不同（hard_sigmoid 对 sigmoid）造成的，专门做了验证，但换成 hard_sigmoid 后结果没有变化，所以这个差距目前还无法解释，只能归为"框架版本差异或随机波动"。
   * 演示脚本中有一个 bug：对 ≥M5.0，LabelEncoder 把类别排成 ['N','X']，第 0 列其实是"负类"，但脚本把第 0 列当成正类概率，导致预测全部反转（v1.0.2 中 TSS 为 −0.679）。改用第 1 列后 TSS 为 0.707，与作者存档输出的一致率为 99.5%。
⑧ 局限：
   * 阈值在测试集上挑选，对稀有类别影响很大；
   * 检查历史行缺失值的代码写错了变量（检查的是 `row` 而不是 `prev_row`），所以缺失的历史行没有被掩码；
   * ≥M5.0 的测试集只有 180 个正样本，而且大多来自少数几个活动区；
   * HMI 数据只覆盖第 24 太阳周，可能存在仪器和太阳周依赖。

### 4.6 CMETNet（Alobaid et al. 2022, Frontiers）

① 一个会影响地球的 CME 从太阳出发后，多少小时到达地球？（回归问题）
② 363 个 ICME（1996–2021 年）。特征包括 CME 角宽度、速度、质量，以及太阳风的 Bz、温度、速度、动压等；另外还有 351 张 LASCO C2 日冕仪 FITS 图像。
③ 随机森林、支持向量回归、XGBoost、高斯过程回归四个模型的预测取中位数（COMB），再与一个处理 C2 图像的 CNN 组合。
④ 留出一个年份作为测试集 → 从其余年份中随机抽 200 个事件训练 → 重复 10 次 → **在测试年份上挑 MAE 最低的那次** → 取中位数集成。
⑤ 到达时间（小时）。
⑥ MAE（论文报告 9.75 h）、皮尔逊相关系数（0.83）。
⑦ 只复跑了数值特征部分（COMB）。我逐年留出了 18 个年份（共 348 个事件）作为测试集：
   * 在测试年份上挑最优那一次（发布版的做法），按事件数加权的 MAE 为 12.36 小时；
   * 改用前一年来挑选，MAE 为 13.09 小时；
   * 完全不挑选、直接取 10 次的平均，MAE 为 13.41 小时。
   18 个年份全部出现了"在测试集上挑最优就会显得更好"的现象，乐观偏差为 0.3–2.9 小时。
   * 论文（Frontiers 全文已读）用的是 2013–2021 年逐年留一，共 9 次：CMETNet 的 MAE 为 9.75 h，纯数值部分（FW）为 10.32 h。
   * 发布数据里 2018–2021 年每年都不足 3 个事件。在能比较的 2013–2017 年上，即使在测试年份上挑选，COMB 的 MAE 也有 14.2 h，达不到论文数字。另外，仓库里的 `pretrained_models_results.py` 只是把**写死的数字**画成柱状图，并没有真正计算。
⑧ 每年的测试事件很少（有的年份只有 1–3 个）；存在选择偏差；CNN 部分没有跑。

### 4.10 SYMHnet（Space Weather 2024）

① 预测 1 或 2 小时后的 SYM-H（1 分钟或 5 分钟分辨率）。
② 42 个地磁暴：第 1–25 个用于训练，第 26–42 个用于测试，按地磁暴划分，这一点做得好。
③ 图神经网络（把各太阳风参数当作图上的节点）+ 双向 LSTM + 蒙特卡洛 dropout。
④ 发布版测试流程：取一行数据作为输入，预测**下一行**。
⑤ SYM-H 值与不确定性。
⑥ RMSE、R²、FSS。
⑦ 存档的 7 个地磁暴，在 1 分钟/5 分钟两种分辨率、1h/2h 两个时长下全部重跑，共 28 次：

   * **关键在于选哪个基线：** 和"1–2 小时持续性"比，技巧分数是 +0.85 到 +0.98，看起来非常好；但发布版测试实际预测的是"下一行"，所以应该和"1 步持续性"比，这时 28 次全部是负数（−0.29 到 −11.7），也就是说还不如直接拿当前值当预测。

   * **用被引版本 v1.0（11 个特征，最新版是 8 个）重跑并和论文 Table 8/9/12 对比：**

⑧ 1h 和 2h 两个数据目录的文件 MD5 完全相同，SYM_H 列也没有做任何平移；因此发布版测试实际上是在做"1 分钟或 5 分钟之后"的预测，和论文"1–2 小时预报"的描述不一致。v1.0 的结果与论文部分吻合，提示论文可能也是这样评估的，但这只是推断，需要作者确认。

### 4.13 SDNN（ApJ 2022）

① 用深度网络代替缓慢的 Milne–Eddington（ME）迭代反演：从 GST/NIRIS 的 Stokes 轮廓（I、Q、U、V）直接得到视向速度、多普勒宽度和磁场（Bx、By、Bz）。
② 每个像素 4 个 Stokes 参数 × 60 个波长点（不足 60 就补零）；输入文件 `cals_170713_162012.fts`（228 MB，正是论文的测试图 D3）从 web.njit.edu 下载。

⑤ 5 张 720×720 的图。
⑥ 论文 Table 1：与 ME 反演比较 MAE、PA、R² 和 PPMCC（D3 的视向速度 PPMCC 为 0.912）。
⑦ **工具层面复现成功**：
   * 发布代码在 Keras 2.10 下直接运行会报错：循环里的 `Lambda` 闭包引用了循环变量。TF1 在建图时只执行一次，所以没有问题；Keras 2.10 每次预测都会重新执行这些闭包。

⑧ 论文 Table 1 需要 ME 反演的结果图，发布包里没有，所以论文层面无法重跑；在 CPU 上处理一张图约需 16 分钟。

### 4.14 SolarCNN（Sol. Phys. 2024）

① 把 MDI 磁图"提升"到接近 HMI 的质量，使 1996–2010 年的历史数据可以和 HMI 时代的数据统一使用。
② MDI 与 HMI 的配对图像（256×256）。
③ 带注意力机制的 CNN；损失为 SSIM 与 L1 的组合。
④ 训练时先截断到 ±2000 G 再除以 2000。
⑤ 增强后的磁图。
⑥ SSIM、PCC、PSNR。
⑦ 复现情况：

### 4.15 DeepHMI（A&A 2025）

① 把 HMI 的 Bz 和横向场（Bt）提升到 GST/NIRIS 的分辨率。
② 1 对 HMI/NIRIS 测试图（AR 12371）。
③ 条件扩散模型：从纯噪声开始，以 HMI 图像为条件，经过 1000 步去噪逐步生成高分辨率图像。
④ 在 CPU 上运行很慢：我实测 U-Net 前向一次约 67 秒，2 个分量 × 1000 步约需 37 小时，在这个环境里不可行（有 GPU 的话几分钟就能跑完）。
⑤ 超分辨率后的 Bz 和 Bt。
⑥ 4 个图像指标，与双三次插值比较。
⑦ 被算力阻塞，没法完整复跑。我改为对作者随仓库提供的输出图重新打分（以 GST 观测为真值）：
   * Bz：SSIM 0.810，优于直接使用 HMI 输入的 0.733；RMSE 190 G，优于 220 G。改进明显。
   * Bt：SSIM 0.659，略差于 0.683；RMSE 206 G，略好于 223 G。好坏参半。
⑧ 扩散模型的输出是随机的，每次运行不完全相同；测试只有 1 张图。

### 4.16 MIST

① 预测未来 24 小时内是否发生 ≥M 级耀斑。
② **我验证了它的数据就是 LSTM 论文 ≥M 的训练文件**（2010–2013 年，84,577 行，逐值一致），选取了其中 16 个特征。
③ 把 24 小时的序列切成 12 个"块"（patch，每块 2 小时）→ 线性嵌入 → 3 层 Transformer 编码器 → 平均池化 → 输出概率。
④ 滑动窗口（第 p 到 p+23 行作为输入，第 p+24 行的标签作为目标）→ **随机 80/20 划分**。
⑤ 概率与类别。
⑥ TSS。
⑦ README 报告的 TSS 0.9062 我精确复现了。但测试窗口和训练窗口大量重叠：
   * Zenodo 存档里有作者自己的训练数组 `X_train.npy`（GitHub 上没有）。我用它直接比对：16,911 个测试窗口中有 16,195 个（**95.8%**）和某个训练窗口有 23/24 小时完全相同，另有 132 个和训练窗口一模一样。
   * 542 个正样本测试窗口里有 522 个存在这种重叠。
   * 这证实了我之前从 CSV 推算的 95.6%。
   把同一个模型拿到 2015–2018 年的独立数据上测试，TSS 只有 0.197；即使用验证集来选阈值，也只有 0.364；AUC 为 0.833。
   * Zenodo 存档的标题是 "A New Deep Learning Method for Solar Flare Prediction"，没有找到同名论文。最接近的是 arXiv:2606.21896（Chaudhary, Wang, Xu, Xu, Zhang 2026）：设计完全相同（16 个特征、24 小时、块长 2、维度 128、2010–2018 年数据、分层随机划分），而且写明阈值是用 Optuna "在测试集上最大化 TSS" 选出来的。
   * 但它报告的数字（准确率 95.18%、recall 0.89、AUC 0.96）与发布模型在发布划分上的结果（99.38%、0.910、0.997）不同，两者应是相关但不同的实验。
⑧ 结论：0.90 主要来自时间重叠导致的泄漏，并不代表真实的预报能力。**这是你外部验证主题的一个完美案例**，而且只用公开数据就能复核。

### 4.17 SINet（JGR 2026）

① 预测未来 1–60 天每日的 F10.7 和 F30。
② NOAA 的 F10.7 数据，日本丰川/野边山的 F30 数据；测试时段为 2009–2021 年。
③ TimesNet 风格的网络：先用 FFT 找出序列中的主要周期（例如 27 天的太阳自转周期），把一维序列折叠成二维，再用 Inception 卷积提取特征。
④ 用过去 30 天的数据预测未来 d 天。
⑤ 未来 d 天的序列。
⑥ RMSE、MAE、MAPE。
⑦ F10.7 的 4 个预测时长与 notebook 中的存档结果逐位一致（例如 1 天 RMSE 3.8801，60 天 16.3241）；F30 与存档结果的差异在 2% 以内（例如 1 天 RMSE 2.0466，存档为 2.0586）。
   我还用完全相同的测试窗口补做了两个朴素基线：①"持续性"（用最后一天的值预测）；②"27 天自转回归"（用一个太阳自转周期之前的值预测）。SINet 在**所有预测时长上都优于这两个基线**：F10.7 的 RMSE 降低 9–13%，F30 降低 2–11%（差距最小的是 F30 的 27 天预报）。这是一个正面结果，说明模型确实学到了东西。
   * **论文层面也复现了**：arXiv 版（2604.10045）报告 F10.7 的 1 天 RMSE 为 3.88、60 天为 16.32，和我跑出来的 3.8801、16.3241 一致；F30 的 60 天为 9.99，我得到 10.1475（差 1.6%）。
⑧ 训练期与测试期的划分方式我没能完整核查，因为训练数据没有随仓库发布；另外还应该与 NOAA 官方预报做比较。

### 4.19 DeepGeoCME（arXiv 2026）

① 判断一个 CME 是否会造成地磁效应（geoeffective）。

### 4.20 MagNet（你邮件里写的那个工具）

* 输入为 MDI 的视向磁图加上 BBSO 的 Hα 图像，输出 Bx 和 By，从而给 1996–2010 年补出"矢量磁图"。训练时以 HMI 的矢量磁图作为"真值"。

  * 代码；
