## 0. 先说结论（一页版）

1. **CCSC 网站本身打不开。** 云端环境把 `nature.njit.edu` 拦了（403），网页抓取工具也解析不了。arXiv、Zenodo 和期刊网站同样打不开。所以我**没能点 Citation 按钮**。工具清单是通过 GitHub 账号 `ccsc-tools`（页面标题即 "Community Coordinated Software Center"）还原的：共 19 个工具仓库，引用信息取自每个仓库的 README/Notebook，以及检索引擎返回的书目信息。这一点在所有报告里都如实写明了。
2. **跑通了大部分工具**（全部在 4 核 CPU、无 GPU 的环境里）：
   * **能精确复现作者存档输出的：** SEP-prediction（12/12 指标逐位一致）、RNN-CME（10/10 预测一致）、SolarUnet（修正文件排序后掩膜逐字节一致）、MIST（TSS 0.9062，和 README 的 0.90 一致）、SINet（F10.7 RMSE 逐位一致）、Kp（在随机性范围内一致）。
   * **能复现但必须加注释的：** FlareML、LSTM、SolarFlareNet、TSInet、CMETNet、SYMHnet。
   * **被阻塞的：** FibrilNet、SDNN（模型挂在 web.njit.edu 上）、SolarCNN（权重文件缺失）、LLMFlare（需要受限的 Llama-3.1-8B、付费的 Gemini API 和 GPU，没有你的授权我不会去用）、MagNet（托管在 nature.njit.edu 上）。
3. **最重要的发现，和你邮件里的主题（外部验证、数据质量）高度相关：**
   * **MIST：** README 报告的 TSS 0.906 来自"重叠滑动窗口 + 随机划分"。95.6% 的测试窗口在训练集里都有一个与之重叠 23/24 小时的"邻居"。我把同一个预训练模型拿到**时间和活动区都独立**的 2015–2018 数据上测试，TSS 只有 **0.197**（AUC 从 0.997 降到 0.833）。而 2019 年那篇 LSTM 论文在同一份测试集上的 TSS 约为 0.73。这正是你邮件里说的"out-of-sample validation"问题的一个具体实例。
   * **Dst Transformer：** 发布版测试代码 `predict()` 会读取测试标签：只要预测值和真实值"不够离谱"，就把它替换成 **0.9 × 真实值**，结果 88–90% 的"预测值"恰好等于 0.9×标签。原始网络输出的 R² 只有 0.06–0.38，在每个预测时长上都不如"持续性预报"（用当前值预测未来）。
   * **SolarFlareNet：** 仓库自带的 9 个模型里，8 个在自带测试集上没有判别能力（AUC 0.40–0.53），作者自己存档的结果文件也是如此。唯一有效的 C/24h 模型是后来重训的，而它的训练文件包含了 84% 的测试行。
   * **SYMHnet：** 发布版测试流程实际上是在预测**下一行**（1 分钟或 5 分钟之后），而不是 1–2 小时之后；1h 和 2h 两个数据目录的文件完全相同（MD5 一致）。
   * **CMETNet：** 训练脚本在"测试年份"上挑选 10 次随机训练中 MAE 最低的那次，属于测试集选择偏差。
   * 也有**做得好的地方**：LSTM 论文的 Table 2 数据集按时间切分（2010–2013 训练 / 2014 验证 / 2015–2018 测试），而且训练和测试之间**没有共享任何活动区**，这是非常规范的 leakage-aware 划分。我用它重训了 10 个随机种子，≥M5.0 的 TSS 为 0.877±0.035（测试集最优阈值）。
4. **对你的意义：** 这些发现本身就是一个很好的"Data Science 视角下的科学 ML 可靠性"研究故事，和 NSF 26-512 "AI-Ready Datasets" 计划（截止日期 2026-11-04）的方向一致。但**措辞必须非常克制**：我们看到的是"发布出来的工具代码和数据包"，不等于"论文的实验做错了"，因为论文的完整代码和全文我们都看不到。具体怎么跟 Jason 讲，见第 6 节。

## 1. 太阳物理/空间天气背景速成

| 概念 | 一句话解释 | 在哪些工具里出现 |
|---|---|---|
| **活动区 (Active Region, AR)** | 太阳表面磁场很强的区域（黑子群），NOAA 给它们编号，例如 AR 12673。耀斑和 CME 大多从这里爆发。 | 几乎所有耀斑/CME/SEP 工具 |
| **SDO/HMI** | NASA 太阳动力学天文台上的日震与磁成像仪，2010 年起提供全日面**矢量磁图**（三个分量 Bx、By、Bz），720 秒一张。 | SHARP 相关工具、DeepHMI、SolarCNN 的标签 |
| **SOHO/MDI** | HMI 的前代仪器（1996–2011），只有**视向（LOS）磁图**，分辨率更低。覆盖第 23 太阳周（比第 24 周更强）。 | SolarCNN、MagNet |
| **SHARP 参数** | 由 HMI 矢量磁图对每个活动区计算出的约 25 个物理量，例如 TOTUSJH（总无符号电流螺度）、USFLUX（总无符号磁通量）、R_VALUE（极性反转线附近的磁通）、TOTPOT（总自由磁能代理量）等。可以理解为"活动区的表格型特征"。 | FlareML、LSTM、SolarFlareNet、SEP、RNN-CME、MIST |
| **耀斑等级（GOES X 射线）** | 按 1–8 Å 软 X 射线峰值通量分级：A < B < C < M < X，每级相差 10 倍；"M5.0" 指 5×10⁻⁵ W/m²。"≥M" 指 M 级及以上。 | 所有耀斑工具 |
| **NCEI / DONKI** | NOAA 的耀斑目录 / NASA 的空间天气事件数据库（记录耀斑、CME、SEP 之间的关联）。 | 标签来源 |
| **CME（日冕物质抛射）** | 大量等离子体和磁场被抛入行星际空间；若朝向地球，可引发地磁暴。 | RNN-CME、CMETNet、DeepGeoCME |
| **SEP（太阳高能粒子）** | 耀斑或 CME 加速出的高能质子，对宇航员和卫星有辐射危害。 | SEP-prediction |
| **地磁指数 Dst / SYM-H / Kp** | 衡量地磁暴强度的指数。Dst（小时值）和 SYM-H（1 分钟值）越负，暴越强；Kp 取 0–9，越大越强。 | Dst、SYMHnet、Kp |
| **太阳风参数** | L1 点卫星测得的行星际磁场（尤其是 Bz 南向分量）、太阳风速度、密度、动压、电场等，来自 NASA OMNIWeb。 | Dst、Kp、SYMHnet、CMETNet |
| **F10.7 / F30** | 10.7 cm / 30 cm 波长的太阳射电流量，是太阳活动水平的"体温计"，用于高层大气密度和卫星轨道衰减模型。 | SINet |
| **TSI（总太阳辐照度）** | 太阳在 1 AU 处的总辐射功率，约 1361 W/m²，变化只有约 0.1%。是气候研究的重要输入。 | TSInet |
| **BBSO / GST / NIRIS** | 大熊湖太阳天文台（NJIT 运营）的 1.6 m Goode 太阳望远镜，以及其近红外成像光谱偏振仪，分辨率远高于 HMI，但视场小、只有部分时间有观测。 | SolarUnet、FibrilNet、SDNN、DeepHMI |
| **Hα 图像 / 纤维 (fibril)** | Hα 是 656.3 nm 的氢谱线，可以显示色球层结构；纤维是沿磁力线排列的细长暗结构，可以用来推断磁场方向。 | FibrilNet、MagNet |
| **Stokes 反演** | 偏振光谱（Stokes I、Q、U、V）经物理模型（如 Milne–Eddington）反演得到磁场和速度。传统方法很慢，所以用神经网络来近似。 | SDNN |
| **SWAMIS** | 传统的磁特征识别与跟踪软件（基于阈值），SolarUnet 用它的输出作为训练标签。 | SolarUnet |

## 2. 评价指标（以及为什么这样选）

**二分类（耀斑 / CME / SEP 预报）**，混淆矩阵记为 TP、FN、FP、TN：

* **Recall（召回率）= TP/(TP+FN)**：真实事件中被预报到的比例。
* **Precision（精确率）= TP/(TP+FP)**：发出的警报中真正发生的比例。在类别极不平衡时通常很低。
* **ACC（准确率）**：类别不平衡时会误导人。例如 ≥M5.0 的正例只占约 0.4%，全部预测为"否"也能得到 99.6% 的准确率。
* **BACC（平衡准确率）** = (recall + specificity)/2。
* **TSS（真技巧评分）= recall − FPR**，取值 −1 到 1。**空间天气领域最常用**，因为它不受正负样本比例影响（Bloomfield et al. 2012 推荐）。TSS=0 表示没有技巧，TSS<0 表示比随机还差（往往是标签方向弄反了）。
* **HSS（Heidke 技巧评分）**：相对于"随机猜测"的改进，受类别比例影响。
* **Brier Score / BSS**：用于概率预报，衡量预报概率与实际 0/1 结果之间的均方误差；BSS 是相对于"气候学基准"的改进比例。
* **AUC**：与阈值无关的排序能力，0.5 代表随机。

**回归（Dst、Kp、SYM-H、F10.7、TSI、CME 到达时间）**：

* **RMSE / MAE**：误差的大小（单位分别是 nT、小时、W/m² 等）。
* **R² / Pearson r**：解释方差的比例 / 线性相关程度。
* **持续性基线（persistence）**：直接用"当前值"作为对未来的预测。对 1 小时后的 Dst、1 分钟后的 SYM-H 这类高度自相关的序列，持续性基线往往非常强。**一个模型要声称有用，至少要先打败持续性基线。** 这是我在多个工具上补做的关键检查。
* **FSS（forecast skill score）**：一般定义为 1 − MSE_model / MSE_reference，参考预报通常取持续性或气候学基准。

**图像（超分辨率、分割）**：

* **SSIM**：结构相似度（亮度、对比度、结构），1 为完全相同。
* **PSNR**：峰值信噪比（dB），越高越好；**它依赖于你设定的数据范围（data_range）**，换一个归一化方式数值就会变。
* **PCC**：像素级皮尔逊相关系数，对线性缩放不敏感。
* **IoU / 像素一致率**：分割掩膜之间的重叠程度。

## 3. 贯穿所有工具的共性问题：数据泄漏与"验证到底验证了什么"

这一节是这次工作的"方法论核心"，也是你 Data Science 背景最能发挥作用的地方。

1. **随机划分 vs 时间/活动区划分。** 太阳数据是强自相关的时间序列：同一个活动区的相邻小时几乎一模一样。如果按样本随机切分，测试样本的"兄弟"往往就在训练集里，模型等于在背答案。
   * 规范做法：LSTM 论文的 Table 2 按时间切分，活动区之间零重叠。
   * 反面例子：MIST（随机切分重叠窗口，TSS 从 0.906 降到 0.197）；SolarFlareNet 自带的测试文件（84% 的行同时出现在训练文件里）。
2. **阈值或模型在测试集上选择。** 只要在测试集上挑"最好的那个"，报告出来的分数就会偏乐观。
   * LSTM Table 5 在测试折上挑选让 TSS 最大的阈值。我量化了它的影响：在 ≥C 上影响很小（0.580 → 0.589），在 ≥M5.0 上影响很大（0.734 → 0.877），因为正样本极少，阈值一动 TSS 就跳。
   * CMETNet 在测试年份上从 10 次训练中挑最好的一次。
   * SEP 在测试集上拟合等距校准（isotonic calibration）。
   * RNN-CME 对每个模型使用固定阈值，这些阈值怎么选出来的不清楚。
3. **归一化统计量包含测试集。** MIST 的 StandardScaler 用全部 84,577 行拟合；FlareML 在测试批次上拟合 scaler；TSInet 用目标序列自身的最小/最大值来缩放输出。
4. **评估路径读取了标签。** Dst 的 `predict()` 会用到 y_test（最严重的一种）。FlareML 的展示函数会改写 RF 的分数，使其低于集成模型。
5. **"预测时长"的实现与描述不一致。** SYMHnet 的 1h 和 2h 数据完全相同，测试目标实际上是下一行；Dst 测试对所有时长都加载 6h 的权重。
6. **有效样本量很小。** SEP 测试集只有 2 个产生 SEP 的活动区；RNN-CME 只有 2 个活动区；SolarCNN 只有 3 张图；DeepHMI 只有 1 张图。在这种情况下，TSS=1.0 的不确定性非常大。
7. **软件工程层面的可复现性问题。** `os.listdir()` 不排序导致文件顺序依赖操作系统（SolarUnet）；命令行参数没有生效（TSInet 缺少 `global` 声明）；特征按"位置"而不是"列名"选取，导致列错位（SolarFlareNet）；模型和数据托管在单一机构的网站上（FibrilNet、SDNN、MagNet），网站一旦访问不了就无法复现。

> 这些全部是**关于发布出来的软件包**的观察。论文正文和原始实验代码我们看不到，所以**不能**据此断言论文的数字是错的。在与教授交流时，请务必保持这个区分。

## 4. 逐个工具讲解（8 点格式）

每个工具按以下 8 点展开：①研究问题 ②输入数据 ③算法 ④运行流程 ⑤输出 ⑥评价指标 ⑦复现情况 ⑧局限性。

### 4.1 FlareML（DeepSun 的后端）

① 已知某天会发生耀斑，预测它是 B、C、M 还是 X 级（4 分类）。
② 845 个耀斑日（2010-05 至 2016-12，472 个活动区），每个样本取耀斑当天 00:00 的 13 个 SHARP 参数（TOTUSJH、TOTBSQ、TOTPOT、USFLUX、R_VALUE 等）。
③ 随机森林（RF）、多层感知机（MLP）、极限学习机（ELM，隐藏层权重随机生成、只训练输出层的一种单隐层网络），再加上三者的多数投票（ENS；平票时采纳 RF 的结果）。
④ 读取 CSV → 去掉非特征列 → 类别字母映射为 1–4 → RF 直接使用原始特征，MLP/ELM 先做标准化 → 三个模型分别预测 → 投票 → 按类别计算 one-vs-rest 的 TSS/BACC 并画柱状图。
⑤ 每个样本一个类别标签。
⑥ 按类别计算的 TSS、BACC。
⑦ 在演示测试集（40 个样本）上，用预训练模型复现了作者日志：ENS acc 0.850，RF 0.825，ELM 0.725，MLP 0.300（MLP 把全部样本预测成 C，作者日志里也是如此）。原始指标见 `results/FlareML/independent_metrics_pretrained.json`。
⑧ 局限：
   * 40 个演示测试样本中有 **31 个同时出现在训练样本里**，所以演示分数不是样本外分数；
   * 展示函数会把 RF 的分数改写为"ENS 减去一个随机数"；
   * MLP/ELM 在测试批次上拟合标准化参数，导致单个样本的预测结果依赖于和它一起测试的其他样本；
   * 只用耀斑当天 00:00 这一个时刻的快照，没有时间序列信息；
   * 4 类严重不平衡（C 级占 65%）。

### 4.2 LSTM-flare-prediction（Liu et al. 2019, ApJ）

① 给定一个活动区在时刻 t 的数据，预测未来 24 小时内会不会发生 ≥M5.0 / ≥M / ≥C 级耀斑。三个阈值各训练一个二分类模型。
② 每小时一个样本，每个样本有 40 个特征：25 个 SHARP 参数，加上 15 个"耀斑历史"特征（例如过去一天发生过多少次 C/M/X 级耀斑、按时间衰减的加权和）。经过特征选择后，三个模型分别使用其中 14、22、20 个。把同一个活动区连续 10 个小时的样本组成一个序列。
③ LSTM（10 个单元）→ 时间注意力（对 10 个时间步加权，再与最后一个隐藏状态拼接）→ 全连接层 200 → 全连接层 500 → softmax。损失函数为加权交叉熵（class_weight='balanced'），训练 7 个 epoch，batch size 256。
④ 读 CSV → 若当前样本存在缺失值则丢弃 → 向前取同一活动区的 9 个历史样本（不足则补零掩码）→ 输入网络得到 P(正类) → 与阈值比较。
⑤ 每个样本输出概率和正/负标签。
⑥ Recall、Precision、ACC、BACC、HSS、**TSS**。
⑦ 复现情况：
   * Table 2 数据重训了 10 个种子。在 2015–2018 测试集上，用测试集最优阈值时 TSS 为 ≥M5.0 0.877±0.035、≥M 0.748±0.021、≥C 0.589±0.009；改用**验证集**选阈值（无泄漏）时分别为 0.825、0.739、0.584；用工具的固定阈值时分别为 0.734、0.730、0.580。
   * 原论文 Table 5（≥C，10×10 交叉验证）：作者的参考输出是 TSS 0.612±0.009；我用同一份代码（只加了 4 行 TF2 兼容补丁）在 TF 2.10 下复跑，共训练 100 次、耗时 86 分钟，得到 **TSS 0.581±0.011**，比作者低 0.031，其他指标也都略低。我怀疑是 Keras 2.2.4 与 TF2 中 LSTM 默认激活函数不同（hard_sigmoid 对 sigmoid）造成的，专门做了验证，但换成 hard_sigmoid 后结果没有变化，所以这个差距目前还无法解释，只能归为"框架版本差异或随机波动"。
   * 演示脚本中有一个 bug：对 ≥M5.0，LabelEncoder 把类别排成 ['N','X']，第 0 列其实是"负类"，但脚本把第 0 列当成正类概率，导致预测全部反转（TSS −0.671）；改用第 1 列后 TSS 为 0.686，与作者存档输出的一致率为 98.9%。
⑧ 局限：
   * 阈值在测试集上挑选，对稀有类别影响很大；
   * 检查历史行缺失值的代码写错了变量（检查的是 `row` 而不是 `prev_row`），所以缺失的历史行没有被掩码；
   * ≥M5.0 的测试集只有 180 个正样本，而且大多来自少数几个活动区；
   * HMI 数据只覆盖第 24 太阳周，可能存在仪器和太阳周依赖。

### 4.3 RNN-CME-prediction（Liu et al. 2020, ApJ）

① 一个活动区已经产生 M/X 级耀斑，那么在未来 12–60 小时内，这个耀斑会不会伴随 CME？
② 18 个 SHARP 参数组成的时间序列；标签通过 NCEI 耀斑目录和 DONKI 中的耀斑–CME 关联确定。
③ GRU 或 LSTM（10 个单元，dropout）+ 注意力 + 全连接层。
④ 构造序列 → 网络输出 P(CME) → 与固定阈值比较（不同模型取 0.40–0.50）。
⑤ 正/负标签。
⑥ TSS 等。
⑦ 10 个模型（GRU/LSTM × 5 个时间窗口）的预测与作者存档输出**完全一致**，TSS 在 0.82–1.00 之间。

### 4.6 CMETNet（Alobaid et al. 2022, Frontiers）

① 一个会影响地球的 CME 从太阳出发后，多少小时到达地球？（回归问题）
② 363 个 ICME（1996–2021 年）。特征包括 CME 角宽度、速度、质量，以及太阳风的 Bz、温度、速度、动压等；另外还有 351 张 LASCO C2 日冕仪 FITS 图像。

④ 留出一个年份作为测试集 → 从其余年份中随机抽 200 个事件训练 → 重复 10 次 → **在测试年份上挑 MAE 最低的那次** → 取中位数集成。
⑤ 到达时间（小时）。
⑥ MAE（论文报告 9.75 h）、皮尔逊相关系数（0.83）。
⑦ 只复跑了数值特征部分（COMB），并量化了"在测试集上挑最优"带来的乐观偏差（逐年结果见英文报告）。仓库里的 `pretrained_models_results.py` 只是把**写死的数字**画成柱状图。
⑧ 每年的测试事件很少（有的年份只有 1–3 个）；存在选择偏差；CNN 部分没有跑。

### 4.7 Dst Transformer（DSTT，FLAIRS 2022）

### 4.9 TSInet（FLAIRS 2021）

### 4.16 MIST
